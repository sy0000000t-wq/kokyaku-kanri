# 電気保安管理 顧客管理ツール

電気管理技術者（個人事業）向けの、保安管理契約物件を一元管理するローカル Web アプリです。
顧客マスタ・点検スケジュール・請求／入金を1つの SQLite ファイルで管理します。

仕様は [電気保安管理_顧客管理ツール_仕様書.md](電気保安管理_顧客管理ツール_仕様書.md) を参照してください。

## セットアップ

```bash
npm install
npm run db:migrate    # SQLite スキーマ作成 + 初期マスタ投入
npm run dev           # http://localhost:3000
```

`npm run db:migrate` は何度実行しても安全です（スキーマは差分適用、マスタは未登録のものだけ追加）。

本番起動:

```bash
npm run build && npm run start
```

### 検証用サンプルデータ

```bash
npm run db:seed:sample
```

`data/sample-customers.json` を読み込みます。このファイルは**実在の顧客情報を含むため `.gitignore` 済み**で、
リポジトリには入りません。ファイルが無い場合はダミーの `data/sample-customers.example.json` が使われます。

## スマートフォンからのアクセス

開発サーバーは `next dev -H 0.0.0.0` で起動するため、同一 LAN 内の端末から見られます。

1. Mac の IP アドレスを調べる

```bash
ipconfig getifaddr en0
```

2. スマートフォンのブラウザで `http://<表示されたIP>:3000` を開く

同じネットワーク（同じ Wi-Fi）に繋がっていること、Mac のファイアウォールが Node の着信を
許可していることが条件です。現場では点検スケジュール画面の「当月の点検リスト」が主用途で、
連絡先はタップで発信、住所はタップで Google マップが開きます。

## データとバックアップ

| 場所 | 内容 |
|---|---|
| `data/app.db` | データベース本体。これ1つで全データが完結します |
| `data/backup/app-YYYYMMDD.db` | 起動時の自動バックアップ。同日分は上書き、30日で自動削除 |
| `data/deleted/*.json` | 顧客を完全削除したときの退避データ |

いずれも `.gitignore` 済みです。

### 復元手順

1. アプリを停止する（`npm run dev` / `npm run start` を Ctrl+C）
2. 戻したい日付のバックアップを本体に上書きコピーする

```bash
cp data/backup/app-20260823.db data/app.db
```

3. `data/app.db-wal` と `data/app.db-shm` が残っていれば削除する
4. アプリを起動し直す

設定 → データ管理から取得した **JSON 一括エクスポート**からも復元できます。
インポートは現在のデータを全置換するため、実行前に必ずエクスポートを取ってください。

## 換算係数テーブルの更新手順

換算係数・点検周期の倍率・施設種別・請求サイクルは、すべて DB から読み込んでいます。
アプリのコードに固定値は書かれていないので、**設定画面から変更すれば全画面に反映されます**。

1. 設定 → 換算係数タブを開く
2. 右上のセレクタで編集するテーブル（需要設備 / 太陽光・蓄電所）を選ぶ
3. 行を編集・追加・削除する
   - 下限は「以上」、上限は「未満」
   - 上限を**空欄**にすると「上限なし」になります（最上位行に1つだけ置けます）
4. レンジの重複・欠落はその場で検証され、エラーがあると保存できません
5. 「このテーブルを保存」を押す

太陽光・蓄電所テーブルには告示に定めのある 5000kW 未満までしか行がありません。
5000kW 以上の物件を登録する場合はここに行を追加してください。

点検周期の倍率（換算係数に掛ける値）は設定 → 点検周期タブから変更できます。
変更すると、その周期を使っている全顧客の保安管理点数と点数単価が再計算されます。

## 距離の算出について

| モード | 使うもの | 精度 |
|---|---|---|
| 道路距離 | Google Geocoding API + Routes API | 番地レベル。所要時間も出ます |
| 直線距離 | OpenStreetMap Nominatim + Haversine | **町・大字レベル** |

設定の距離算出モードが「自動」のとき、API キーがあれば道路距離、無ければ直線距離になります。

距離は**顧客の保存時と「再計算」ボタンを押したときだけ**算出し、結果は DB にキャッシュします。
一覧を開くたびに API を叩くことはありません。

### 直線距離モードの制約

Nominatim は日本の番地・小字をほとんど収録していません。そのため住所を
「全体 → 番地を落とす → 町/村まで → 市/区/郡まで」の順に丸めながら再試行します。
つまり**得られる座標は町・大字の代表点**で、実際の物件から 1〜2km ずれることがあります。

また Nominatim は自由文検索であいまい一致するため、放っておくと別の市の施設が返ることがあります
（実際に「愛知県豊田市仮町仮田」で豊橋市の保育園が返る例がありました）。
そのため都道府県と市区郡が一致しない結果は破棄しています。

正確な距離が必要な物件は、顧客編集画面の「緯度・経度を手入力する」から座標を直接入れてください。
手入力した座標は住所を変えても保持されます（住所だけを変えた場合はキャッシュを捨てて取り直します）。

Nominatim の利用規約に従い、リクエストは 1 秒に 1 回までに制限しています。
一括再計算に時間がかかるのはこのためです。`.env.local` の `NOMINATIM_USER_AGENT` に
連絡先を含む User-Agent を設定してください。

## API キーの扱い

Google Maps API キーは次の順で解決されます。

1. `.env.local` の `GOOGLE_MAPS_API_KEY`（**推奨**）
2. 設定画面で保存した値

**設定画面から保存したキーは SQLite に平文で入ります。** `data/app.db` を人に渡したり
クラウドに置いたりする場合は注意してください。`.env.local` は `.gitignore` 済みです。

```bash
cp .env.local.example .env.local
# エディタで GOOGLE_MAPS_API_KEY を記入
```

## 契約解除と削除

物件を対象から外す方法は2段階あります。**通常は「稼働停止」を使ってください。**

| 操作 | 効果 |
|---|---|
| 稼働トグルを OFF（解除日を入力） | 解除日以降のスケジュール・請求対象から外れる。実績・チェックはすべて残る |
| 顧客編集画面の「削除」（二段階確認） | 顧客と関連実績を削除。削除前に `data/deleted/` へ JSON を自動退避 |

各画面の既定フィルタは「稼働中のみ」です。「すべて」に切り替えると解除済みの行が淡色＋
「解除（日付）」バッジで表示されます。集計値は表示中の行ではなく、常に稼働中の行が対象です。

## 開発

```bash
npm test          # 計算ロジックのユニットテスト
npm run test:watch
npm run build     # 型チェック込みの本番ビルド
```

計算ロジックは `lib/calc/` に純関数として置き、UI からは計算式を持ち込まない方針です。

| ファイル | 内容 |
|---|---|
| `lib/calc/coefficient.ts` | 換算係数・保安管理点数（§4.1） |
| `lib/calc/pricing.ts` | 月額・年額・点数単価（§4.2） |
| `lib/calc/schedule.ts` | 実施月の生成、稼働判定、点検対象の導出（§4.4） |
| `lib/calc/billing.ts` | 請求月・請求額・入金予定・未入金判定（§4.5） |
| `lib/calc/coefficient-range.ts` | 換算係数テーブルのレンジ検証（§5.7） |
| `lib/geo/` | 距離算出。`GoogleProvider` / `HaversineProvider` を差し替え可能 |

仕様書 §4 の検証ケース（A社（サンプル） 0.48／36,458 円、B社（サンプル） 0.60／28,889 円）は
テストに入れてあり、`npm test` で既存シートとの一致を確認できます。

## 要確認事項・実装メモ

- **施設種別に係数テーブルを2つ持たせています。** 仕様書 §3.3 の表には `coefficient_table_id`
  しかありませんが、「需要設備＋太陽光」は kVA 側と kW 側の係数を合算する必要があるため、
  `secondary_coefficient_table_id` を追加しました。設定 → 施設種別タブの
  「合算する係数テーブル」がこれにあたります。
- **請求月は請求サイクルから毎回導出しています。** 点検月（`customer_inspection_months`）と違って
  テーブルには保存していません。点検月のように月単位で手修正したい場合は、
  同じ形のテーブルを足す必要があります。
- **未入金の判定は「請求済みのもの」だけを対象にしています。** 請求チェックを付けていない過去月を
  未入金として赤く出すと、単に未処理なだけの月まで警告になってしまうためです。
  未請求の月は請求リストの「未請求のみ」フィルタで拾えます。
- **TypeScript は 6 系に固定しています。** Next.js 15 は TypeScript 7 のネイティブコンパイラに
  対応していません。TypeScript 7 を使う場合は Next.js 16.2.11 以降へ上げてください。
- **`npm audit` に transitive な指摘が出ます。** Next.js が抱える postcss / sharp、
  drizzle-kit が抱える esbuild のものです。`npm audit fix --force` は Next.js の
  ダウングレードを伴うため当てていません。LAN 内からのみアクセスする前提の運用です。
